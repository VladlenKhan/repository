# XAU/USD Telegram Bot

Телеграм-бот с аналитикой по золоту: индикаторы, уровни поддержки и
сопротивления, макрофон, подписка на утреннюю сводку и уведомления
о пересечении ценой заданного уровня.

Работает на Netlify Functions — постоянно запущенного сервера нет,
код просыпается только на входящий запрос или по расписанию.

> ⚠️ Учебный проект. Все сообщения с анализом заканчиваются строкой
> «Это не финансовая рекомендация» — это не формальность, а суть:
> бот показывает расчёты, а не советы.

## Возможности

| Команда | Что делает |
| --- | --- |
| `/start` | приветствие и список команд |
| `/analysis [таймфрейм]` | разбор рынка: цена, тренд по EMA 50/200, RSI(14), ATR(14), ближайшие уровни, текущая сессия |
| `/levels` | полный набор пивот-уровней на D1 и H4 |
| `/macro` | реальная доходность облигаций США и её обычное влияние на золото |
| `/subscribe`, `/unsubscribe` | подписка на утреннюю сводку |
| `/alert 2400` | уведомить, когда цена пересечёт уровень |
| `/alerts`, `/alerts_clear` | список и очистка уведомлений |
| `/lang` | переключение языка (русский / английский) |

Таймфреймы: `15min`, `1h`, `4h`, `1day`. Понимает и привычные сокращения —
`H1`, `M15`, `4H`, `D1`.

Автоматически:
- **утренняя сводка** подписчикам по будням в 06:00 UTC;
- **проверка уведомлений** каждые 15 минут (в выходные пропускается).

## Стек и почему именно он

| Технология | Роль | Почему |
| --- | --- | --- |
| [grammY](https://grammy.dev) | Telegram-бот | современный, с хорошей типизацией, умеет вебхуки через `std/http` |
| Netlify Functions v2 | хостинг | стандартные `Request`/`Response`, без серверов |
| Netlify Blobs | хранилище | подписчики, уведомления, кэш свечей |
| [trading-signals](https://github.com/bennycode/trading-signals) | индикаторы | нативный ESM, ноль зависимостей, активно развивается |
| Twelve Data | цены | есть XAU/USD на бесплатном тарифе |
| FRED | макроданные | официальный источник ФРС, бесплатный |
| Vitest | тесты | быстрый, из коробки понимает ES-модули |

**Про выбор библиотеки индикаторов.** Рассматривались два варианта:

| | `technicalindicators` | `trading-signals` |
| --- | --- | --- |
| Последняя публикация | июль 2023 | август 2026 |
| Формат модулей | CommonJS | нативный ESM |
| Зависимости | `@types/node@^6` | нет |

Проект целиком на ES-модулях, а CommonJS-пакет пришлось бы подключать
через интероп-обёртку — на сборке serverless-функций это типовой источник
сбоев. Плюс пакет без обновлений три года — сомнительный выбор для
портфолио.

## Архитектура

```
netlify/functions/      точки входа (их вызывает Netlify)
  bot.mjs               вебхук Telegram, путь /api/bot
  morning.mjs           утренняя сводка, расписание 0 6 * * 1-5
  alerts.mjs            проверка уведомлений, расписание */15 * * * *

lib/                    вся логика
  config.js             чтение и проверка переменных окружения
  bot.js                сборка бота: команды и обработка ошибок
  i18n.js               словарь сообщений (ru / en)
  format.js             сборка текстов — чистые функции
  prices.js             адаптер Twelve Data + кэш
  macro.js              FRED
  indicators.js         обёртка над trading-signals
  levels.js             пивот-уровни
  sessions.js           торговые сессии и часы работы рынка
  analysis.js           сценарии «разобрать рынок» и «посчитать уровни»
  alerts.js             логика уведомлений
  storage.js            Netlify Blobs
  telegram.js           отправка сообщений вне обработчика бота
  timeframes.js         таймфреймы и их разбор

scripts/set-webhook.js  регистрация вебхука в Telegram
tests/                  тесты (сеть замокана)
```

Два правила, которым подчинён код:

1. **Расчёты отделены от ввода-вывода.** `levels.js`, `sessions.js`,
   `indicators.js` и `format.js` не ходят в сеть и не знают про Telegram.
   Поэтому они тестируются без единого мока.
2. **Источник данных спрятан за адаптером.** Чтобы добавить OANDA или
   Finnhub, достаточно написать в `prices.js` функцию с теми же методами
   `getCandles` и `getQuote` — остальной код менять не придётся.

## Что понадобится

Четыре значения. Все бесплатные.

### 1. Токен бота у @BotFather

1. Откройте в Telegram [@BotFather](https://t.me/BotFather).
2. Отправьте `/newbot`.
3. Введите отображаемое имя бота (любое, например «Аналитика золота»).
4. Введите username — он должен быть свободен и заканчиваться на `bot`,
   например `my_xau_analytics_bot`.
5. В ответ придёт строка вида `8123456789:AAH...` — это и есть
   `TELEGRAM_BOT_TOKEN`.

Токен даёт полный контроль над ботом. Не коммитьте его. Если
засветили — `/revoke` у @BotFather выдаст новый.

### 2. Ключ Twelve Data

1. Зарегистрируйтесь на [twelvedata.com](https://twelvedata.com/register).
2. Откройте [API Keys](https://twelvedata.com/account/api-keys) и
   скопируйте ключ — это `TWELVE_DATA_API_KEY`.

Бесплатный тариф: 800 кредитов в сутки, 8 в минуту. Как бот в них
укладывается — в разделе [Ограничения](#ограничения-и-бюджет-запросов).

Проверить ключ и доступность инструмента:

```bash
curl "https://api.twelvedata.com/time_series?symbol=XAU/USD&interval=1h&outputsize=3&apikey=ВАШ_КЛЮЧ"
```

### 3. Ключ FRED

1. Заведите аккаунт на
   [fredaccount.stlouisfed.org](https://fredaccount.stlouisfed.org/login/secure/).
2. Запросите ключ на странице
   [API Keys](https://fredaccount.stlouisfed.org/apikeys) — выдаётся сразу.

Это `FRED_API_KEY`. Используется только командой `/macro`: без него
остальной бот работает, а `/macro` честно сообщит, что не настроена.

### 4. Секрет вебхука

Произвольная случайная строка. Telegram будет присылать её в заголовке
`X-Telegram-Bot-Api-Secret-Token`, а бот — отвергать запросы без неё.
Без секрета на публичный адрес функции может написать кто угодно.

```bash
openssl rand -hex 32
```

Результат — в `TELEGRAM_WEBHOOK_SECRET`.

## Локальный запуск

```bash
git clone <адрес репозитория>
cd xau-predictor
npm install

cp .env.example .env
# откройте .env и впишите четыре значения выше

npm run dev          # netlify dev на http://localhost:8888
```

Понадобится [Netlify CLI](https://docs.netlify.com/cli/get-started/) —
он уже в `devDependencies`, отдельная установка не нужна.

**Важно про локальную разработку.** Telegram не может достучаться до
`localhost`. Чтобы проверить бота вживую, нужен публичный адрес —
например, через [ngrok](https://ngrok.com):

```bash
ngrok http 8888
# затем зарегистрируйте вебхук на выданный адрес:
URL=https://ваш-адрес.ngrok-free.app npm run set-webhook
```

**Функции по расписанию в `netlify dev` сами не запускаются.** Это не
поломка — так устроен CLI. Вызывать вручную:

```bash
netlify functions:invoke alerts
netlify functions:invoke morning
```

## Деплой на Netlify

### Вариант через интерфейс сайта

1. Залейте проект на GitHub.
2. На [netlify.com](https://app.netlify.com) нажмите
   **Add new site → Import an existing project** и выберите репозиторий.
3. Настройки сборки Netlify подхватит из `netlify.toml` — менять ничего
   не нужно.
4. Откройте **Site configuration → Environment variables** и добавьте:

   | Переменная | Значение |
   | --- | --- |
   | `TELEGRAM_BOT_TOKEN` | токен от @BotFather |
   | `TELEGRAM_WEBHOOK_SECRET` | ваша случайная строка |
   | `TWELVE_DATA_API_KEY` | ключ Twelve Data |
   | `FRED_API_KEY` | ключ FRED |
   | `DEFAULT_LANG` | `ru` или `en` (необязательно) |

5. Запустите деплой (**Deploys → Trigger deploy**).

Переменную `URL` задавать не нужно — Netlify подставляет её сам.

### Вариант через CLI

```bash
npx netlify login
npx netlify init        # привязать папку к сайту
npx netlify env:import .env
npx netlify deploy --prod
```

Netlify Blobs включается автоматически — ничего настраивать не надо.
Расписания функций тоже берутся из кода при деплое.

## Регистрация вебхука

После первого успешного деплоя:

```bash
URL=https://ваш-сайт.netlify.app npm run set-webhook
```

Скрипт зарегистрирует адрес `https://ваш-сайт.netlify.app/api/bot`,
передаст секрет и покажет состояние по данным Telegram.

Он также напечатает строку `TELEGRAM_BOT_INFO={...}`. Это необязательная
оптимизация: grammY на каждом холодном старте спрашивает у Telegram имя
бота (`getMe`), а эта переменная избавляет от лишнего сетевого запроса.
Добавьте её в переменные окружения Netlify — на бесплатном тарифе,
где у функции всего 10 секунд, запас лишним не бывает.

Удалить вебхук (например, чтобы временно переключиться на локальную
разработку):

```bash
npm run delete-webhook
```

## Тесты

```bash
npm test              # прогон один раз
npm run test:watch    # перезапуск при изменениях
```

Покрыты расчёт уровней, определение сессий, разбор данных FRED, логика
уведомлений, адаптер Twelve Data и сами команды бота. Все сетевые
запросы замоканы — тесты не ходят в интернет и не тратят лимиты API.

Отдельно стоит отметить несколько тестов, которые закрепляют неочевидные
решения:

- `/levels` **обязан** запрашивать D1 и H4 параллельно — тест считает
  одновременные запросы и требует ровно два в полёте;
- утренняя сводка делает **один** запрос к API независимо от числа
  подписчиков;
- при сбое поставщика данных пользователь получает **ровно одно**
  сообщение об ошибке.

## Ограничения и бюджет запросов

**Время выполнения.** На бесплатном тарифе Netlify обычная функция
живёт 10 секунд, функция по расписанию — 30. Поэтому:

- таймаут на каждый сетевой запрос — 4 секунды;
- вебхук отвечает Telegram не позже чем через 8 секунд (иначе Telegram
  будет повторять тот же апдейт, и пользователь получит дубли);
- независимые запросы идут параллельно через `Promise.all`;
- свечи кэшируются в Blobs на четверть таймфрейма.

**Кредиты Twelve Data.** Бесплатный тариф: 800 в сутки, 8 в минуту.

| Что | Расход |
| --- | --- |
| проверка уведомлений (96 запусков в будни) | 96 в сутки |
| утренняя сводка | 1 в сутки |
| команды пользователей | десятки, благодаря кэшу |

Выходные не расходуют ничего: функция уведомлений выходит до обращения
к API, потому что рынок золота закрыт с вечера пятницы до вечера
воскресенья.

**Точность сессий.** Границы сессий заданы в UTC и не учитывают переход
на летнее время — реальные часы Лондона и Нью-Йорка плавают на час.
Для подсказки «сейчас Лондон» этого достаточно; торговых решений на
этом не строится.

## Частые проблемы

**Бот не отвечает.** Проверьте, что вебхук зарегистрирован:

```bash
curl "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"
```

В ответе смотрите на `url` и `last_error_message`. Логи функции —
в Netlify: **Logs → Functions → bot**.

**Приходит «Эта команда пока не настроена».** Не задан ключ API для этой
команды. Проверьте переменные окружения на Netlify и перезапустите
деплой — переменные подхватываются при сборке.

**Приходит «Лимит запросов исчерпан».** Израсходованы кредиты Twelve
Data. Подождите или уменьшите частоту проверки уведомлений в
`netlify/functions/alerts.mjs`.

**Сообщения приходят дважды.** Признак того, что функция не укладывается
в 10 секунд и Telegram повторяет апдейт. Посмотрите длительность вызова
в логах Netlify.

**Уведомления не срабатывают.** Проверка идёт раз в 15 минут и только
в будни. Убедитесь, что расписание зарегистрировалось: в Netlify
**Site configuration → Functions** у `alerts` должно быть указано
расписание.
